# CineRooms 手機體驗恢復與首屏優化設計

日期：2026-07-30
狀態：已確認方向，待規格審閱
行為基準：`3bd8fb2`（`10fcbf3` 大型優化前的直接版本）

## 背景

近期前端優化後，手機首頁出現數項退化：

- 漢堡按鈕會切換成關閉圖示，但彩色側邊選單仍停留在畫面外。
- 首頁重新出現網格模式，且該模式會被儲存在 `localStorage`。
- 手機搜尋結果改成雙欄海報網格。
- 新增標語與篩選選項後，兩排篩選器占用過多首屏高度，使用者需要滑動較長距離才看到書脊。
- 管理員登入後的浮動新增按鈕會覆蓋書櫃內容。

舊版手機功能本身已成熟，因此本次不重做既有互動。實作以 `3bd8fb2`
為行為參考，選擇性恢復退化功能，再加入已由使用者確認的首屏壓縮調整。

## 目標

1. 恢復舊版可靠的手機選單與首頁檢視行為。
2. 手機首頁只提供書櫃與疊卡，讓書脊更早進入可視範圍。
3. 將影視類型與電影類型濃縮成一排，保留 CineRooms 的膠囊設計語言。
4. 讓手機搜尋結果容易掃讀，不使用密集海報網格。
5. 改善管理員手機操作，但不改變一般訪客看到的內容。
6. 保留近期版本中與退化無關的效能、翻譯及無障礙改善。

## 非目標

- 不全面回滾 `10fcbf3`。
- 不重新設計桌面首頁、書櫃或疊卡。
- 不改變後端 API、資料模型、管理員驗證或部署架構。
- 不在這次加入多選篩選、篩選歷史或新的影評分類。
- 不刪除 `CompactGrid`，除非實作時確認已無任何有效使用者。

## 採用方案

採用「選擇性恢復舊版」：

- 從舊版恢復已驗證的選單載入與動畫方式。
- 從首頁移除近期新增的網格檢視入口及其持久化影響。
- 保留新版的錯誤狀態、API 摘要查詢、翻譯、焦點管理與 ARIA 標記。
- 僅在手機斷點加入新的單列篩選摘要、首屏間距及管理員入口調整。

未採用的替代方案：

- **整版回滾：** 會一併失去近期有效的效能與無障礙修正。
- **重寫整套手機元件：** 變更範圍過大，也違反「舊版功能已完善」的基準。
- **只補動畫例外處理：** 無法處理網格、搜尋與首屏高度等其他退化。

## 詳細互動設計

### 1. 側邊選單

- 保留原本彩色分層、由左側滑入的視覺。
- 恢復舊版同步載入 GSAP 的行為，避免按鈕狀態已開啟、動畫模組卻尚未可用。
- 開啟狀態由同一個 `open` 狀態控制；關閉後面板與彩色前置層回到畫面左側。
- 若動畫執行拋出例外，立即直接設定面板的顯示／隱藏位置；內容顯示不可依賴動畫成功。
- 保留新版的 `aria-expanded`、Escape 關閉、背景捲動鎖定、焦點循環與路由切換後自動關閉。
- 手機管理員選單新增「新增影評」項目，點擊後關閉選單並開啟既有編輯器。
- 桌面版仍顯示原本的浮動新增按鈕；手機版不顯示浮動按鈕。

### 2. 手機 Hero 與垂直節奏

- 手機主標題較目前縮小約 12%，以 `clamp()` 約束 360–430px 寬度，避免窄機型溢出。
- 桌面標題尺寸不變。
- 標語保留；標語底部到手機篩選摘要列之間維持約 30px 的可見空間。
- 移除手機上的負上邊距重疊；需要的桌面重疊效果只在桌面斷點啟用。
- 不以固定螢幕高度定位書櫃，避免 Safari 動態工具列造成跳動。

### 3. 手機篩選器

手機將目前兩排完整膠囊改成同一排的兩個摘要膠囊：

- `影視 · 全部`：全部、電影、影集、動漫。
- `類型 · 全部`：全部類型以及既有電影類型。
- 摘要顯示目前選取值，並帶有下拉提示圖示。
- 兩顆按鈕平均使用可用寬度；文字過長時省略，不把畫面撐成第二排。
- 點擊任一摘要後，從底部開啟單選面板。
- 點選項目後立即套用並關閉，不需要額外「套用」按鈕。
- 點擊背景、按 Escape 或使用關閉按鈕皆可關閉。
- 面板包含標題、目前選取狀態、至少 44px 點擊高度與底部安全區。
- 開啟時鎖定背景捲動並管理焦點。
- 搜尋進行中沿用現有規則：首頁篩選不可操作，避免搜尋結果與分類狀態混淆。
- 桌面仍顯示完整的兩排篩選膠囊，不改變目前操作方式。

### 4. 首頁檢視模式

- 首頁只提供舊版的書櫃與疊卡。
- 不顯示首頁網格切換按鈕。
- 初始化時若 `cinelog_view_mode` 是近期版本留下的 `compact`，自動回復成 `shelf`，並更新持久化值。
- 書櫃仍為沒有有效偏好時的預設值。
- 不修改書櫃抽出、插回、讓位或疊卡翻閱行為。

### 5. 手機搜尋結果

- 搜尋覆蓋頁維持新版的對話框語意、焦點控制與背景捲動鎖定。
- 結果改為單欄列表，不呼叫 `CompactGrid`。
- 每筆至少顯示海報縮圖、片名、影視類型與年份，以及有資料時的分數與最近觀看日期。
- 整列可點擊，點擊目標至少 44px，文字允許合理換行。
- 空結果、載入中與 API 錯誤沿用 `ReviewFeed` 的既有語意。
- 桌面搜尋行為不在本次改動範圍。

## 元件與資料流

預計涉及：

- `HomePage.jsx`：恢復兩種檢視模式、手機 Hero 與篩選摘要、控制底部篩選面板，並傳入管理員新增動作。
- `StaggeredMenu.jsx`：恢復舊版可靠的動畫載入路徑，接收可選的管理員新增回呼。
- `StaggeredMenu.css`：僅補必要的安全區或層級修正。
- `SearchOverlay.jsx`：使用手機單欄結果模式。
- `ReviewFeed.jsx`：明確區分首頁書櫃／疊卡與搜尋單欄模式。
- 新的輕量元件：手機篩選摘要／底部單選面板，以及手機搜尋結果列。

篩選的 `genre` 與 `mediaFilter` 仍由 `HomePage` 持有。底部面板只改變既有狀態，
不建立第二份已套用狀態，避免同步錯誤。

## 響應式與可及性要求

- 主要手機驗證寬度：360、390、430px。
- 桌面回歸驗證寬度：768、1024、1440px。
- 支援 iPhone `safe-area-inset-top` 與 `safe-area-inset-bottom`。
- 所有控制具備可見焦點、可辨識名稱、正確的 expanded／pressed／checked／dialog 語意。
- 手機點擊區域至少 44×44px。
- `prefers-reduced-motion` 下不以動畫作為顯示內容的必要條件。
- 選單或底部面板即使動畫失效，內容仍必須能顯示及操作。

## 驗證策略

### 自動化

- 本次不新增瀏覽器或 React UI 測試框架；互動行為依下方手動矩陣驗證。
- 將檢視模式正規化抽成純函式並以既有 `node:test` 測試：`shelf`、`deck` 正常恢復，其他值（包含 `compact`）回復為 `shelf`。
- 若篩選摘要文字或搜尋顯示模式能抽成不依賴 DOM 的純函式，以既有 `node:test` 覆蓋其輸入與輸出；否則不為了本次變更新增測試框架。
- 執行完整 `npm run check`，包含 ESLint、既有 Node 測試與正式建置。

### 手動

在 360、390、430px 寬度逐項確認：

1. 漢堡選單可連續開關，面板、彩色層、焦點與頁面捲動皆正常。
2. 主標題不溢出，標語與篩選有約 30px 間距。
3. 兩個篩選摘要保持單排，底部面板不被瀏海或 Home Indicator 遮住。
4. 首頁只見書櫃與疊卡，歷史 `compact` 偏好不會重新顯示網格。
5. 書脊比目前版本更早出現在首屏中。
6. 搜尋結果為單欄，長片名、無海報與無分數資料均不破版。
7. 一般訪客沒有新增入口；管理員可從手機選單新增影評。

在桌面斷點確認完整篩選列、書櫃與疊卡均無回歸，且管理員浮動新增按鈕仍存在。

## 完成標準

- 使用者截圖中的三個主要問題已消失：網格入口、失效選單、標語與篩選過近。
- 手機首頁保留書櫃與疊卡，且書脊更早可見。
- 影視與類型篩選在手機維持一排並完整可操作。
- 管理員手機畫面沒有覆蓋書櫃的浮動按鈕。
- ESLint、測試與正式建置通過。
- 前端部署後，以實機或等效手機尺寸完成冒煙測試。
